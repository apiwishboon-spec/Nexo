# Nexo v2.3.4

Bluetooth reliability, sync fixes and Home-screen polish.

## Bluetooth / PIN

- **Random "wrong PIN" failures.** The firmware allowed several BLE centrals at
  once, but responses are broadcast and there is one shared auth session, so a
  second app/instance could receive another client's replies (including
  `Unauthorized`). The device now serves **one central at a time**: it stops
  advertising while connected, rejects extra links, and uses the real connection
  handle when pausing for Wi-Fi bulk transfers.
- **Reconnects kept using an old PIN.** Changing the PIN in the app now updates
  the cached PIN. If a cached PIN is rejected, it is cleared and the half-open
  link is closed so the next connect prompts for the current PIN.
- The PIN dialog shows the default (`123456`), explains how to change it in
  Settings, and auth errors say what to do instead of just "Unauthorized".

## Sync and transfer

- **Only the first page was ever pulled.** After the first `SYNC_PULL` the app
  replaced the `since` value with the device's current epoch, so page 2 returned
  nothing and the remaining changes were marked as synced. The `since` value now
  stays fixed for the whole pull, and every page is applied.
- **Large changes no longer overflow a message.** Firmware list/sync pages are
  capped by bytes as well as record count, and the app splits dirty records into
  several `SYNC_PUSH` requests. Previously a page of long notes, or a batch of
  dirty notes, could exceed the frame limit and fail the whole sync.
- The protocol message limit is now 8192 bytes so a single maximum-size note
  still fits, and a single oversized record is sent alone rather than dropped.
- Documentation now states that the device version wins on a conflict rather
  than promising a conflict prompt that did not exist.

## UI

- Home character animation now steps about every 1.4 s instead of every 14 s.
- Toasts expire after 4 s (with a one-time repaint) instead of staying forever.
- Timer/stopwatch screens repaint at most every 50 ms instead of on every loop.

## Testing

- Native unit tests: **27/27 passed**, including paging that unions every change,
  byte-budgeted pages, and a regression test for the 14-second animation.
- Host UI navigation test: **7/7 rows** open the expected screen.
- Host UI render test passes (no full-screen clears during animation).
- `pio run -e m5stack-cardputer` succeeds; `flutter analyze` is clean;
  `flutter test` passes **32** tests, including new sync paging and push-batching
  tests.
- Not verified on physical Cardputer hardware (none available); CI builds the
  firmware image and both apps.
