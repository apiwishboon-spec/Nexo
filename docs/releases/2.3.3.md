# Nexo v2.3.3

Menu fix, animation flicker fix and documentation updates.

## What's fixed

- **Home menu opened the wrong screen (#1).** The menu order changed in v2.3.0
  (Memos moved ahead of Settings), but the selection handler still used
  positional indices. Selecting **Memos** opened Settings, **Settings** opened
  About, and **About** wrapped around to Memo. Menu labels and actions now come
  from a single table (`nexo_menu.h`), so they cannot drift apart again. The new
  "UI navigation test (host)" exercises all seven rows in CI.
- **Screen flashed while animating.** Every Home-character frame (every 700 ms)
  and every memo recording/playback tick (300–500 ms) called `Ui::draw()`, which
  starts by clearing the whole 240×135 panel. Animation frames now repaint
  incrementally:
  - `drawHomeCharacterFrame()` clears only the one-pixel strip exposed by the
    character's bob and redraws the sprite.
  - `drawMemoLive()` repaints only the blinking REC dot and elapsed time, or the
    single "playing" row.
- **Preview renderer built again.** `firmware/tools/preview/preview_main.cpp`
  still referenced the removed Music screen, so `build_preview.sh` failed.
  Removed the dead references and renumbered the remaining renders.

## Testing

- Native unit tests: **25/25 passed** (includes menu label → target mapping).
- Host UI navigation test: **7/7 rows** open the expected screen.
- Host UI render test: **0 full-screen clears** during Home animation and memo
  recording. The test fails against the pre-fix code, so it guards the
  regression.
- `pio run -e m5stack-cardputer` succeeds; `flutter analyze lib` is clean.
- Not verified on physical Cardputer hardware (none available); CI builds the
  firmware image and both apps.
